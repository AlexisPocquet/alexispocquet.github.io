I'm a master's student in theoretical computer science at the MPRI (Master Parisien de Recherche en Informatique, IP Paris). I'm mainly interested in type theory, proof assistants, programming language theory and static analysis, with an additional focus on homotopy theory and category theory. More generally, I like to see structures, dynamics and geometries arising from the mathematical objects I study.

Research Experience

M1 Research Internship march 2026 → july 2026

Université Paris-Saclay, LMF, Deducteam · Thibaut Benjamin

For my last M1 semester, I worked on augmenting the dependent type theory CaTT (a type theory for globular weak ω-categories) with cylindrification rules, and a translation from it into Homotopy Type Theory.

[more][less]

Type-theoretically, it allows us to exhibit a complex transport structure for Martin-Löf types, which is hidden by the usual study of their higher structure using the J eliminator. Categorically, it allows us to synthetically study a class of deep naturality constructions in weak ω-categories.

L3 Research Work january 2025 → july 2025

CNRS, ENS Paris, Antique · Jérôme Féret and Jérôme Boillot

Over my last L3 semester, I worked on Abstract Interpretation and OS verification on IA-32. I studied the reduced product construction for abstract domains, then introduced an intermediate language with formal semantics and a sound over-approximation stable under task execution.

[more][less]

Abstract Interpretation, introduced by Radhia and Patrick Cousot in the late 1970s, formalizes program analysis as computations over over-approximations of reachable states — ensuring termination while retaining enough precision to infer meaningful invariants. The reduced product is a general construction for combining abstract domains; my semester work studied several instantiations, including those based on input/output channels and ghost quantities.

Programming projects

MiniGoLang 2026

École Polytechnique, Compilation

A compiler for a fragment of Go, following a more disciplined approach than KawaLang — monadic error accumulation across the full front-end, a typed-AST rewriting pass, and x86-64 code generation.

[more][less]

Unlike KawaLang, which was not not stable nor very well designed, this compiler accumulates diagnostics via a dedicated Error monadic style module and separates concerns between the rewriting and emission phases. The compiler passes all provided test cases, including nested struct access, forward calls, and mutually recursive functions. See the implementation report for details.

TinyProver fall 2025

École Polytechnique, Computational Logic

An interactive proof assistant developed for the computational logic course at École Polytechnique, implementing two independent provers in OCaml: one for propositional logic via STLC, one for a minimal kernel of dependent type theory.

[more][less]

The STLC prover supports bidirectional type checking and an interactive tactic mode with sequent manipulation. The dependent types kernel implements the core of Martin-Löf type theory: substitution, parallel beta-reduction, alpha-conversion, and bidirectional inference for Pi-types, natural numbers, and propositional equality. The hardest part was normalization: a naive fixpoint fails on terms defined by recursion over Nat, requiring a more careful reduction strategy.

MiniRust spring 2025

ENS Paris-Saclay, Programmation 2

A partial implementation of Rust's ownership discipline, developed for the advanced functional programming course at ENS Paris-Saclay. The pipeline runs a type checker and a borrow checker before emitting C.

[more][less]

The borrow checker handles the common cases but does not cover all edge cases. On the backend, the most technically involved part is struct dependency resolution: a postfix DFS over a dependency graph ensures definitions are emitted in the right order, with cyclic dependencies through indirection handled implicitly. 91 of 94 tests pass. Here is a set of test cases used to validate the implementation.

KawaLang 2024

Université Paris-Saclay, Théorie des langages de programmation

A sequential interpreter for an object oriented toy language. It is quite unstable but still works enough to check all the tests we were meant to check. Still, the design is crap as it does not distinguish between the IO of the compiler and its analysis phases, and as the semantics of the language is naively thought.
